# 转ppt：忠实重建为可编辑 PowerPoint

## 输入与边界

- “转ppt”默认指将当前提供的图片逐页重建成对象级可编辑 `.pptx`，不是把整图贴进幻灯片。多张图默认每张一页，按附件顺序。
- 缺少图片时只询问图片；来源或排序存在影响结果的歧义时询问关键问题。不要把图片转写成新内容、重排为另一种风格或擅自补字。看不清的字应标出待确认，并在定稿前解决。
- 默认沿用原图配色、版式和内容。页面实际尺寸按下文优先级确定；没有目标模板或明确尺寸时保留原图宽高比。原图与目标页面比例不同时等比例适配并留白，不裁切或拉伸内容。
- 不增加原图没有的 banner、logo、页眉页脚或装饰。原图已有的内容应保留，除非用户要求删除。

## 默认后台验证与前台操作边界

- 常规转换默认只做后台生成、结构检查和无界面渲染对比，不打开 Finder、PowerPoint/WPS 等前台窗口，不抢占焦点、鼠标、键盘或剪贴板。渲染方式须确认不会弹出窗口；后台渲染不可用时如实说明限制，不自动转为桌面操作。
- 应用已安装或工具能控制电脑，不代表获得前台操作授权。只有用户明确要求应用内测试，或针对具体故障同意前台验证后，才执行相关测试；已有明确授权不重复询问。普通“转ppt”及一般修复请求不自动授权占用桌面。
- 前台测试只覆盖当前故障或用户指定的验收项，在临时副本中操作。改色问题只测相关改色路径；仅当修复涉及共用文字格式等关联机制时，才增加必要回归。禁止每次转换完整执行改字号、改色、追加文字、列表编辑、复制及保存重开整套测试。
- 下文所有应用内操作、选中框检查、保存重开及复制实测均受本节约束，是按需测试方法，不是常规交付必做项。静态检查与后台视觉检查仍按要求完成；通过后可交付，无需为补齐可选实测等待用户同意。
- 报告仅陈述实际完成的验证，不将后台渲染称为 PowerPoint/WPS 实测。常规交付简述“已完成结构检查与后台渲染检查，未做应用内实测”即可；具体故障或指定验收项未实测时，单独说明该项，不列出整套无关测试清单。

## 建立尺寸依据

### 先确定目标页面的实际尺寸

- 用户提供用于承接转换页面的 PPT/PPTX 模板或目标演示稿时，先读取其 `ppt/presentation.xml` 中 `p:sldSz` 的 `cx`、`cy`，以原始 EMU 值作为输出页面尺寸；不能只判断“同为 16:9”，也不能用四舍五入后的厘米值重新计算。用户另有明确尺寸要求时遵从；与目标模板冲突且用途不明确时再询问。
- 当前任务已确认的目标模板继续有效，无需每页重复索取。仅作为内容来源的 PPT 不自动视为目标模板；不要将某一次客户模板的尺寸硬编码为所有任务的默认值。
- 无目标模板及明确尺寸时，默认宽度为 `12192000 EMU`（13⅓ 英寸），高度按原图宽高比计算到整数 EMU。不要按“图片像素 ÷ 100”等任意方法确定物理尺寸，也不要从截图 DPI 推断演示稿尺寸。未提供目标稿时可按此默认值执行，但不能声称已与未知模板匹配。
- 先固定最终物理尺寸，再计算坐标、文字大小和整数字号。禁止先在大画布上制作，再依靠跨文件粘贴缩小。既有稿件需适配模板时，应在生成源中同步调整位置、形状、线宽及文字，按最终尺寸重新校准整数字号与换行；不能只改页面宽高，或仅把缩放后的小数字号取整就交付。

先查看原图，记录画布 W×H，以及主要文字、icon、框体和箭头的像素包围盒。OCR 仅用于辅助识字和定位，必须对照原图复核；不要直接接受 OCR 给出的字号。

选定幻灯片物理尺寸后，所有对象使用同一比例映射：`x_pt=x_px×slide_width_pt/W`，高度同理。字号估计应参考字形实际可见高度、行距与字体度量，再通过渲染校准，不能把 OCR 文本框高度直接当字号。

### 文字比例是硬要求

- 文字用原生文本框，保留原文、换行、强调、对齐和字号层级。以文字相对于画布、卡片和 icon 的可见大小为准，不套用统一小字号。
- 连续段落或同一连续正文块使用一个文本框，通过框内段落、换行和富文本设置保留原图排版；禁止按视觉行或 OCR 行拆成多个独立文本框。局部加粗、变色也在同一文本框内处理。只有独立标题、不同栏或不同卡片等实际分离的内容区域才分开建框。
- 识别到原图中的项目符号列表时，使用 PowerPoint 原生段落项目符号格式（如 DrawingML `a:pPr/a:buChar`），不要在正文文本中手动输入“•”“·”等圆点，也不要用独立圆形或文本框模拟项目符号。同一内容区域的一组列表保留在一个文本框内，每个条目是独立段落；条目内自动换行或软换行不新增项目符号。用段落左边距和悬挂缩进设置符号与正文间距，使续行与正文起始位置对齐，不以空格凑对齐。保留原图的符号样式、相对大小、颜色、列表层级和条目间距；仅作为正文标点的圆点不转为列表。原图为连续编号列表时使用原生自动编号，业务编号或标题编号不擅自改成自动编号。
- 字号使用整数 pt，例如 10、12、14，也可使用符合原图比例的其他整数；不输出 10.5、12.3 等小数字号。将估算字号校准到最接近原图视觉大小的整数，同层级统一；不要为了凑偶数或套用示例字号而缩小原图文字。取整后重新检查换行和溢出，优先调整文本框与段落参数，不启用自动缩字。
- 如无特殊要求，文本框的自动调整设置使用“根据文字调整形状大小”（DrawingML `a:spAutoFit`）。不要设为“不自动调整”（`a:noAutofit`）或“溢出时缩排文字”（`a:normAutofit`）。保持整数字号，通过形状尺寸适应文字；导出后检查尺寸变化是否导致越界、重叠或破坏原图布局。该默认值针对文本框，不能因此让表格单元格或承载文字的业务图形任意变形。
- 禁止通过自动缩小文字以适应文本框来解决溢出。应先检查字体替代、框内边距、行距、字距、文本框尺寸和换行；仍有冲突时忠实调整位置或说明问题，不悄悄缩字。
- 同层级文字保持一致；原图本来小的注释可以保持原比例，不强制放大。对比同尺寸渲染图，文字可见高度明显变小即需修复；可将偏差超过约 10% 作为复查提示，但该阈值不能替代目视判断。
- 如无特殊要求，默认字体使用用户指定的完整字体家族名 `Microsoft YaHei UI`，正文 Regular、强调按需 Bold；不要替换为 `Microsoft YaHei`、等线或主题字体。用户明确指定其他字体或要求保留原图字体时遵从。默认字体改变后仍需按原图复核文字比例、字号层级和换行。核实生成与渲染环境中该字体是否可用；字体菜单显示名称不能单独证明渲染器使用了该字体。缺失时说明替代字体及预览限制，不静默改掉交付文件的指定字体，也不将替代预览称为指定字体实测。不能将原图文字保留在背景里再叠加另一份可编辑文字。

### 纯图形尺寸与跨文件复制

- `a:spAutoFit` 的默认值只适用于真正的文本框（`p:cNvSpPr/@txBox="1"`），不能批量用于横条、背景框、箭头或原生矢量 icon。`has_text_frame` 为真不代表对象是文本框；许多普通形状也带空的 `p:txBody`。
- 纯图形必须保留明确的几何尺寸。生成时优先不写空的 `p:txBody`；需要保留空文字容器时使用 `a:noAutofit`，禁止 `a:spAutoFit`。删除容器前确认没有文字、字段或需保留的内容；不得删除业务图形中的实际文字，也不得全局把所有 `a:noAutofit` 改成 `a:spAutoFit`。文本框继续执行前述自动调整规则。
- 复制后出现细横条变方块、背景框压成窄条或图标纵向变形时，检查纯图形是否带空文字容器及 `a:spAutoFit`，再结合源文件、目标稿尺寸和实际复制方式判断。修复须回写生成代码，并确认文字、图形坐标、几何路径和填充未被意外改动；渲染正常不能替代跨文件复制实测。

### 新输入文字的字体继承

- 不能只设置现有文字 run 的字体。每个重建文本框须在 `a:rPr`、段落 `a:pPr/a:defRPr`、段落末尾 `a:endParaRPr` 和软换行 `a:br/a:rPr` 中显式设置适用的字体；在文字 run、段落末尾和软换行格式中显式设置整数字号，不在重建文本框的段落 `a:pPr/a:defRPr` 上重复写入 `sz`（见下方字号编辑兼容性规则）。中英文和数字至少同时设置 `a:latin`、`a:ea` 为 `Microsoft YaHei UI`，复杂文字脚本按实际语言及字体覆盖设置 `a:cs`。空段落也应有明确的默认及末尾格式，避免删除文字、末尾追加或回车时回退到主题字体。
- 段落默认格式保留对应字体及粗细，不重复固定字号；段落末尾格式采用对应正文或标题的整数字号及粗细；保留既有局部强调，不把最后一个强调片段的样式无条件扩散为整段默认。字体补全不能重新引入段落红色回退、覆盖主题色语义或破坏项目符号。按 DrawingML 的合法子元素顺序写入：项目符号属性在 `a:defRPr` 之前，`a:endParaRPr` 在段落内容末尾；修改已有属性时避免重复字体节点。
- 从零生成演示稿且未指定其他主题字体时，同步设置输出文件的默认文本样式、母版/版式文本样式及主题标题/正文字体的中英文映射（包括简体中文 `Hans`），使新增内容默认一致。有目标模板时保留模板中用户要求的字体策略；对重建文本框显式设定默认及末尾格式，不为修一页而改动用户整份原稿的主题。不能保证粘贴到任意其他 PPT 后仍不受目标主题影响，须按实际粘贴方式验证。
- 导出后检查上述字体设置完整且没有意外的等线、Calibri 或主题占位字体回退。针对新增文字字体问题且已获前台测试授权时，在测试副本中按问题需要验证：现有文字末尾追加中文、英文和数字；按 Enter 新建普通段落与项目符号条目；清空一个测试文本框后重新输入。检查新输入文字的字体及整数字号，保存、关闭、重开后复查。只读文件结构或只看已有文字正常，不算新增文字字体验证通过；无法实测时明确标注未完成。

### 字号编辑兼容性

- 已复现的 PowerPoint 案例：标题直接字号与段落 `a:pPr/a:defRPr/@sz` 均为 19 pt，手动输入 18 后，应用移除了 run 的直接字号，文字重新继承段落 19 pt；输入 28 则正常。该现象不能归因于用户操作，也不能凭一个其他字号成功就宣布字号编辑正常。18 是已知回归用例，不代表所有模板或应用都固定以 18 为默认。
- 新重建文本框避免在 `a:pPr/a:defRPr` 重复写 `sz`；现有文字、软换行及段落末尾保留明确的整数字号，段落默认字体继续使用 `Microsoft YaHei UI`。不要为了规避字号问题删除默认字体、项目符号、颜色或粗细。应用保存后省略直接字号可能是合法继承，须检查实际生效字号，不一律判坏。
- 修复既有文件时先复制并记录故障前格式。若文字或字段依赖段落默认字号，先解析实际字号并落实到内容对应的直接格式，再移除已确认造成覆盖的段落字号；不得全局删除母版、版式、主题或其他有用途的默认字号。修复回写生成代码，并检查文字、有效字号、字体、颜色和几何位置未变。
- 针对字号编辑问题且已获前台测试授权时，在测试副本中选中代表性文本框，验证原字号改为 18、另一个不同整数，以及增大和减小字号；原字号已是 18 时先改为另一整数再返回 18。有目标模板时也检查其实际默认字号。核对可见文字变化，保存、关闭、重开、重新选中后复核有效字号；不能只看字号输入栏短暂变化。涉及跨文件粘贴时在目标稿副本测试。
- 若修复影响字体继承且已获前台测试授权，按相关影响回归末尾追加中英文数字、Enter 新段落或清空后重新输入，确认字体及整数字号正常继承。保持“根据文字调整形状大小”，不以自动缩字掩盖问题。无法完成的应用测试明确标为未完成；`check_font_sizes.py` 的静态通过不能代替手动改字号测试。

### 文字颜色与跨文件编辑

- 新重建的文字在各个文本 run 上直接设置实际字体颜色，保留局部多色；不要仅在段落默认样式中设置红色，再让所有 run 依赖它。需要随主题变化的文字保留主题色语义，不擅自转成固定 RGB。直接设置颜色仍允许用户在 PowerPoint 内改色，并非锁定颜色。
- 既有 PPT 中的段落颜色继承是合法结构，不能只因存在 `a:defRPr/a:solidFill` 就宣布文件损坏或已找到故障原因。排查时先在工作目录复制文件，保留故障前状态；记录具体文字、单选或多选、主题黑色或自定义 RGB 黑色、源稿或目标稿。
- 按需运行 `python3 <skill-root>/scripts/text_colors.py <文件.pptx>` 获取颜色结构报告。需要整理段落颜色时，使用 `--output <新的临时文件.pptx>`；该脚本依赖 `lxml`，可使用已提供的文档运行时。它将已知段落填充复制到缺少直接填充的 run，然后移除对应段落填充，保留混合色和已有直接格式，不覆盖原文件。无法解析的母版/版式颜色会拒绝写入，应在生成源中解析，不能猜黑色。
- 整理工具是兼容性修复候选，不是已确认的主题黑色修复方案。采用其结果前，核对文字与有效颜色没有变化，重新渲染；只在验证支持时保留改动，并将相同处理纳入生成源，避免下次导出回退。

### 形状原色、渐变与 PowerPoint 兼容性

- 按原图取样并复核文字、形状、边框的实际颜色，不套用默认蓝色或主题强调色。原图为渐变时保留其色标、位置、方向、透明度及明暗过渡，优先使用原生可编辑渐变；不能用纯色替代渐变后声称忠实还原。避开文字边缘、抗锯齿和压缩噪声取样，并与同尺寸渲染对照。
- 写入 `p:spPr` 等形状属性时遵守 DrawingML 子元素顺序：变换、几何、填充、轮廓、效果、三维属性、扩展。`a:gradFill` 必须位于 `a:ln`、`a:effectLst` 等节点之前；已有轮廓时不能直接 `append(gradFill)` 到末尾。使用 XML 库的有序插入方法，移除冲突的旧填充，保留唯一有效填充。修复必须回写生成代码，不能只修最终文件。
- 渐变内部先写 `a:gsLst`，再写方向（`a:lin` 或 `a:path`），最后写可选 `a:tileRect`；检查色标位置为 0–100000 且按序排列、颜色定义有效、透明度及方向参数正确。图片重建中已确定的颜色显式写入色标；需要主题语义时保留并核实主题映射。`a:fillRef` 本身是合法继承，不能仅因它存在就删除主题或断言根因；但无效渐变可能导致应用回退到主题填充。
- 含原生渐变的输出，交付前运行 `python3 <skill-root>/scripts/check_gradients.py <最终文件.pptx>`，要求退出码 0 且 `passed: true`。该只读脚本检查常见节点顺序、填充冲突、色标位置、RGB、基础透明度与角度；不解析完整主题与颜色变换，不等于完整 OOXML 校验、原图配色验收或 PowerPoint 实测。
- 用户反馈形状整体变蓝或预览与 PowerPoint 不一致时，先保留故障副本，对比渐变结构、主题继承与应用实际显示；不能先归因于用户设置或只调整 RGB。针对该显示故障且已获前台测试授权时，在修复副本中实际打开并核对背景、分区及箭头渐变；涉及保存或跨文件复制的问题，按实际操作保存、重开或在目标稿副本中复测。只有渲染器正常不得宣称 PowerPoint 修复通过；无法实测时明确说明已完成的检查和未完成的应用验证。

### Icon 比例与可改色

- 保留 icon 的宽高比、相对文字尺寸、视觉重量、线宽和留白；禁止拉伸或仅换成语义相似但造型明显不同的素材。
- 识别到作为文字配图的小 icon（如上升柱状图、AI 芯片）时，默认将整个 icon 重建为一个完整的矢量对象，不按柱子、箭头、芯片引脚或内部字母等组成元素拆成独立 PPT 对象；也不以一组零散形状代替完整矢量图。对象级可编辑不要求拆开 icon 的每个细节。
- 小 icon 优先使用单个 SVG 图形对象，或单个支持复合路径的原生自由形状，支持整体选择、移动、缩放和改色。SVG 内部可有多个路径，但在 PPT 中应作为一个完整图形；icon 内部固定字母（如 AI）可转为矢量轮廓，旁边的业务文字仍用独立可编辑文本框。只有用户明确要求拆解内部元素时才拆分。
- 较复杂 icon 优先描摹或矢量化成干净 SVG；转换为 PPT 自由形状时也应保持整体对象。多色 icon 在一个矢量资产内保留颜色区域，不为逐区域编辑而默认拆散。SVG 应包含真实路径，使用可修改的 `fill`/`stroke`，不得内嵌位图冒充矢量。
- 矢量 icon 保留在 PPT 内即可，默认不单独生成或交付 SVG 文件及图标包；仅在用户明确要求时另行导出。制作所需的临时 SVG 可保留在任务工作目录，不作为交付物。如果 PPT 内只能嵌入 SVG，应如实说明其为矢量图片、可能需要“转换为形状”后改色。未经实际验证，不宣称可直接在 PPT 内修改每个部分颜色。
- 位图自动描摹后检查孔洞、轮廓、线宽和多色分区。无法忠实矢量化的复杂照片或纹理允许保留位图，并明确列为限制；不能将其称为可改色 icon。

### 自由形状边界与选中空白

- 自由形状的选中框应贴合实际轮廓。使用 `python-pptx` 时，将真实首点传入 `build_freeform(start_x, start_y, scale=...)`，随后添加线段；不能先用默认 `(0,0)` 初始化、再 `move_to` 到真实首点，留下不绘制但扩大边界的孤立起点。真实轮廓本来经过 `(0,0)` 时正常保留，不按坐标值一概删除。
- 修复多余边界须在生成源中删除已确认无用的移动命令，并同步重算路径视口、形状偏移与尺寸；保留多子路径、孔洞及整体箭头。核对修复前后的页面绝对轮廓位置，不能只缩小外框而压缩图形。边界变化也会改变渐变映射，须重新核对渐变的视觉位置及颜色，必要时重算渐变，而非仅核对色标值不变。
- 交付前运行 `python3 <skill-root>/scripts/check_shape_bounds.py <最终文件.pptx>`。要求 `passed: true`，并逐项复核 `reviews`：脚本拦截扩大边界的孤立移动点；较大留白只提示复核，允许有设计依据的统一图标视口。曲线仅使用控制点包围范围，弧线、公式坐标等报告检查限制，不能将未检查内容视为边界通过。结合渲染及可用的应用选中框检查，确认无异常大片空白；脚本不自动裁切或修改文件。

### 箭头必须是整体形状

- 保留原图箭身宽度、箭头头部宽高、转折、方向、填充和边框。块状箭头优先采用 PowerPoint 原生整体箭头形状。
- 原生预设无法匹配时，用一个连续封闭的自由形状路径重建完整箭头，转折和头部属于同一个几何对象。
- 禁止用若干线段加三角形拼出块状或转折箭头，也不能通过组合这种拼接对象伪装整体箭头；避免接缝、双边框和重叠色块。
- 如果原图确实是细线连接箭头，优先使用带原生箭头端点的单个预设连接符（直线、折线或曲线）。预设无法忠实表达路径时，使用单个开放路径自由形状 `p:sp/p:spPr/a:custGeom`，保留细线轮廓、虚线及原生箭头端点；不能用独立线段或三角形拼箭头头部。自由形状不具备连接符的自动吸附/重连语义，不能宣称二者行为完全等同。
- **PowerPoint 已复现兼容性陷阱**：`p:cxnSp/p:spPr/a:custGeom` 曾在 Mac PowerPoint 中触发“内容有问题”，自动修复会丢弃所在页面内容，而 XML Schema、现有结构检查及其他渲染器均可通过。这是已知应用兼容性问题，不等于该组合违反 OOXML Schema。新生成文件不得使用这一组合；`p:cxnSp` 使用 `a:prstGeom`，自定义路径使用 `p:sp/p:spPr/a:custGeom`。
- 修复已有自定义路径连接线时，先保留故障副本，回写生成代码，并同步处理对象及非可视属性类型（`p:cxnSp` → `p:sp`、`p:nvCxnSpPr` → `p:nvSpPr`、`p:cNvCxnSpPr` → `p:cNvSpPr`）。检查原有连接引用、锁定和扩展属性是否适用于新类型，不仅改外层标签；保留对象 ID、路径、位置尺寸、轮廓、虚线和箭头端点。不要全局转换正常的预设连接符，不把 PowerPoint 自动修复删除内容后的文件直接当作交付稿。

## 执行与验证

使用当前环境可用的 PPTX 库或绘图工具生成原生对象；按需加载运行时依赖。此技能不强制依赖另一个转换技能或其专用 CLI。批量页面可以顺序完成。

重建前先分离背景与前景。文字、可几何化框体、箭头和 icon 分别建立对象；照片允许用图像对象。不能以整页截图作为最终页面，也不能保留含有文字和图形的整图底板再覆盖重复对象。

交付前同时通过两类检查：

列表 XML 必须遵循 DrawingML 子元素顺序：`a:buClr`、`a:buSzPct`、`a:buFont`、`a:buChar`（或 `a:buAutoNum`）应在 `a:defRPr` 之前；用 XML 库插入时不能直接追加到已有 `a:defRPr` 后面。仅统计到 `buChar` 不代表 PowerPoint 能识别。需要保留原图断行时使用同一条目内的软换行，并显式设置换行字符的字号，防止继承异常。

列表检查：确认项目符号位于段落格式而非正文字符中，条目未按视觉行拆框，续行与正文对齐，且没有重复圆点。针对列表编辑问题且已获前台测试授权时，在测试副本中通过工具栏更换或取消项目符号，并在条目末尾按 Enter 验证新条目延续列表格式；仅验证 XML 时不宣称已完成应用内列表编辑测试。

1. **视觉检查**：通过无界面方式实际渲染 PPTX，以与原图相同画布尺寸并排或叠加对比。逐页检查文字大小、实际字体、换行、溢出、icon/文字比例、图形位置、箭头头部与转折、颜色和遮挡。发现明显缩字、变形或接缝必须修复后重渲染。
2. **结构检查**：验证 PPTX 可被文件解析器读取、页数与输入一致、关系引用完整；检查文字为文本对象、连续正文未被逐行拆框、最终生效字号为整数 pt（包括富文本及继承样式），块状箭头是整体预设或单一自由形状，icon 的矢量资产无位图伪装。仅有文件生成或 ZIP 校验通过，不等于视觉通过。

### 连接线兼容性检查（交付必做）

运行 `python3 <skill-root>/scripts/check_connector_compatibility.py <最终文件.pptx>`，要求退出码 0 且 `passed: true`。该只读脚本检查幻灯片、母版、版式及组合内的 `p:cxnSp/p:spPr/a:custGeom`，报告文件部件与对象 ID；不自动改写文件，也不替代整体格式或应用行为验证。脚本维护时运行 `python3 -m unittest discover -s <skill-root>/scripts -p 'test_connector_compatibility.py'`，使用不含业务内容的合成样例验证问题组合被拦截、预设连接符与自由形状箭头不误报。

针对打开或保存故障，或用户明确要求打开验证，且已获前台测试授权时，在最终文件的验证副本中实际打开，确认无修复提示、页面和对象完整；保存、关闭、重新打开后复查，不能把 LibreOffice 渲染或 ZIP/XML 检查当作 PowerPoint 实测。修复提示仍存在时，继续定位，不以接受自动修复作为通过依据。应用不可用、控制失败或用户正在操作导致测试中断时，明确区分已完成的打开/保存/重开步骤与未完成步骤，不宣称整套验证通过。

### 目标模板匹配与复制验证

有目标模板时，导出后运行 `python3 <skill-root>/scripts/check_slide_size.py <最终文件.pptx> --template <目标模板.pptx>`，要求 `passed: true`；同时执行下方字号检查。尺寸比较必须使用 EMU，宽高比相同不算尺寸匹配。

用户反馈复制后字号变小或出现小数时，先核对源文件与目标稿的实际尺寸，并区分“整页复制”“对象复制”“文字粘贴”；再检查粘贴主题、占位符继承、自动缩字与组合缩放。等比例缩放会改变数值字号，但不必然改变文字在页面中的相对比例；不能未经对照就断言某一个原因，也不能把“保留源格式”当作尺寸匹配的替代办法。

针对跨文件复制问题或用户指定的复制验收，且已获前台测试授权时，在目标稿的临时副本中验证复制后的字号、换行和对象大小，不修改用户原稿。若无法进行应用内复制验证，应区分“页面尺寸与文件结构已核对”和“复制行为已实测”；不得仅凭渲染或 ZIP 校验宣称打开、复制与编辑完全正常。

### 字体改色实测

针对字体改色问题且已获前台测试授权时，在临时副本中按故障涉及的选择方式和颜色检查代表性的有色标题与连续正文：单选文本框、选中文字，以及多选同类文本框后，分别改为“主题黑色/文字 1”、自定义 `RGB 0,0,0` 和一种其他颜色。检查可见文字实际改变，并保存、关闭、重新打开测试副本确认；仅工具栏色块改变不算通过。最终交付仍保留原图颜色。

故障或指定验收涉及目标稿，且已获前台测试授权时，在目标稿临时副本中按用户实际的整页复制或对象粘贴方式检查相关颜色、字号与换行。不要把源文件测试当作目标稿测试，不在用户正在编辑的原稿上做改色或撤销试验。

主题黑色失败而其他颜色成功时，记录具体差异，再对比整理前后的文件进行同一操作；不能用“改成红色成功”替代“改成主题黑色成功”。自定义纯黑可以作为临时尝试，但未经验证不保证有效。测试可能改变软件状态；操作后故障消失不等于定位根因，也不意味着用户此前操作有误。

无法操作应用或测试工具失败时，完成结构与渲染检查，明确“主题黑色/跨文件复制未实测”，不得宣称修复成功或编辑完全正常。不要为了获取通过结果而删除相关检查。

### 整数字号自动检查（交付必做）

最终导出后运行 `python3 <skill-root>/scripts/check_font_sizes.py <最终文件.pptx>`。必须返回退出码 0 且 `passed: true` 才能报告整数字号检查通过；仅运行技能格式校验不算 PPTX 验证。此脚本只读取文件，不自动修复。

脚本检查 DrawingML 字号、小数、自动缩字、组合缩放，以及文本框是否使用 `a:spAutoFit`、非文本框的空图形是否误用 `a:spAutoFit`（`empty_graphic_shape_autofit`）。若字号继承无法解析，脚本保守报错：先解析实际字号，再在生成源中显式写入整数字号；不得随意套用默认字号。若组合对象存在缩放，先归一化坐标并校准实际文字大小。检查失败时在生成源修复、重新导出、重新运行检查，并渲染复核换行与溢出。不要只改最终 PPTX 而让下一次导出恢复错误。

脚本通过仅证明其列出的结构检查通过，不证明 PowerPoint/WPS 中的实际显示或视觉质量。若用户反馈与文件检查不一致，先说明已验证事实，定位具体文字和文件版本，不预先断定失败原因。

检查小 icon 在 PPT 中是否为单个 SVG 图形对象或单个复合路径自由形状，不能仅因零散元素已分组就判定满足整体矢量规则。后台可在验证副本中修改图形属性并渲染，检查相应改色结果；需要应用内直接改色验收且已获前台测试授权时，选取代表性 icon，在验证用副本中修改整体图形颜色或原生形状的填充/轮廓并渲染，确认有效；保留最终稿原色。若仅验证了 SVG 源码可改色，应明确这与 PPT 内直接改色不同。

若环境无法渲染或验证，应如实报告未完成的验证，不宣称质量验收通过。

## 中间文件与清理

- 默认只交付一个已验证的最终 `.pptx`，所需矢量图标内嵌；简洁预览优先直接展示，不另交付预览包、测试稿、SVG 图标包或重复成品，除非用户要求。
- 必要中间材料集中到 `work/<本次转换>/`，按需分为素材、渲染及验证子目录，不将每个图标和试验版本平铺到工作目录或最终输出目录。复用相同素材；SVG 已满足嵌入和验证时，不机械地为每个图标额外生成 PNG。仅在实际兼容性或渲染需要时生成替代格式。
- 完成后清理本次创建且已确认无用的失败尝试、重复成品和多余预览，保留必要生成源及其依赖，保证后续修改可复现。仅清理可确认归属本次任务且不再被引用的中间文件；不删除用户原始材料、独立版本、既有文件或未提交的技能修改。故障副本在排查结束前保留。
- 中间文件不是交付物，不逐个向用户列出，不为整理文件打开 Finder。此规则不授权清理其他任务或历史目录。

## 交付

默认仅交付 `.pptx` 并提供简洁预览，矢量 icon 随 PPT 内嵌交付；不单独生成 SVG 交付文件或图标包，除非用户明确要求。说明页数、可编辑范围、验证结果及仍保留为位图的具体对象；没有限制时不添加泛化免责声明。

转换后的最终 PPTX 默认将唯一的真实成品保存到用户 Downloads / 下载文件夹。当前任务的 `outputs/` 如需提供交付入口，只创建指向该真实文件的符号链接，不复制第二份实体成品；确认链接目标存在且可读取，并如实说明真实文件位置与链接关系。若无法创建链接，不以复制文件替代。Downloads 写入受限时使用可用审批机制；若仍无法写入，将唯一真实成品保存到当前任务的 `outputs/`，明确说明实际位置，不声称已保存到 Downloads。用户在当前任务中明确指定其他位置时遵从。除非用户要求多份副本，不在 Downloads、outputs 或 work 保留重复的最终成品；必要生成源与素材仍按中间文件规则保留，不据此删除历史文件或覆盖同名既有文件。此规则针对转换产物，技能本身仍安装在技能发现目录。

技能维护只更新安装目录；除非用户另行要求，不生成或更新 Downloads 技能备份。
